# API contract (T07)

| File | What | Generated by |
|---|---|---|
| [openapi.json](openapi.json) / [openapi.yaml](openapi.yaml) | REST API, OpenAPI 3.1 (153 operations) | `python backend/scripts/openapi.py` |
| [asyncapi.yaml](asyncapi.yaml) | WebSocket `/ws/market`, AsyncAPI 3.0 | `python backend/scripts/asyncapi.py` |

Both are generated from the code; CI fails when they are out of date (`--check`), validates the
AsyncAPI file and generates both clients below on every pull request. Human guides: the other
files in [docs/](..). The live API also serves the document at `/openapi.json` and Swagger UI at
`/docs` in development; **both are off in production** (this folder is the public contract).

## What the document guarantees

- **operationId** `<tag>_<function>`, e.g. `market_list_instruments`, `posts_create_post`,
  `subscriptions_checkout`: stable names for generated methods.
- **Tags** per domain (`auth`, `market`, `strategies`, `backtests`, `workspaces`, `notifications`,
  `news`, `posts`, `price-alerts`, `experts`, `subscriptions`, `chat`, `admin`, …).
  `payments-demo` holds the demo provider's pages and the payment webhook (no login; a real
  provider would replace them).
- **Security** per operation: `BearerJWT` (`Authorization: Bearer <access token>`) for account
  endpoints that refuse API keys; `BearerJWT` **or** `ApiKey` (`X-API-Key: tk_…`, with the scope
  the endpoint needs) for the readable data; none for public endpoints (health, register,
  login, the demo payment pages).
- **Errors**: every documented error (400, 401, 403, 404, 409, 422, 429, 502, 503) uses the shared
  `Error` schema `{"detail": "…" | [{loc, msg, type}], "retry_after"?: int}`; 422 also allows
  FastAPI's validation format. 429 answers carry `Retry-After` and `RateLimit-*` headers.
- **Examples** on the main request bodies (register, login, API key, strategy activation,
  backtest, custom strategy, workspace, post, comment, price alert, checkout, chat message, …).

## Web (TypeScript)

Types with [openapi-typescript](https://openapi-ts.dev), calls with `openapi-fetch`:

```bash
npx openapi-typescript@7.4.4 docs/api/openapi.json -o src/api/schema.d.ts
npm install openapi-fetch
```

```ts
import createClient from "openapi-fetch";
import type { paths } from "./api/schema";

const api = createClient<paths>({ baseUrl: "http://187.127.76.76:8080" });
api.use({ onRequest: ({ request }) => { request.headers.set("Authorization", `Bearer ${token}`); return request; } });
const { data, error } = await api.GET("/api/v1/market/instruments", { params: { query: { limit: 50 } } });
```

## Mobile (Flutter, dart-dio)

With [openapi-generator](https://openapi-generator.tech) (Java 11+; the npm wrapper downloads
the generator jar):

```bash
npx @openapitools/openapi-generator-cli@2.15.3 version-manager set 7.10.0
npx @openapitools/openapi-generator-cli@2.15.3 generate \
  -i docs/api/openapi.json -g dart-dio -o packages/trading_api \
  --additional-properties=pubName=trading_api
cd packages/trading_api && dart run build_runner build --delete-conflicting-outputs
```

or without Node: `docker run --rm -v "$PWD:/w" openapitools/openapi-generator-cli:v7.10.0 generate
-i /w/docs/api/openapi.json -g dart-dio -o /w/packages/trading_api`.

The generator warns that OpenAPI 3.1 support is still marked "in development" and renames a few
model names that are Dart reserved words (`ModelNull`, `ModelSource`); the client generates
and the operations are complete. Methods are named after the operationIds
(`TradingApi.marketListInstruments(...)`).

## WebSocket

There is no generator for the socket in either app; use `asyncapi.yaml` as the reference (it
lists every client op, topic and server message with JSON Schemas). Render it with
`npx @asyncapi/cli start studio docs/api/asyncapi.yaml` or the AsyncAPI Studio website.

## Regenerating

```bash
cd backend
python scripts/openapi.py      # after changing routes or schemas
python scripts/asyncapi.py     # after changing app/realtime/protocol.py or WS payloads
python scripts/erd.py          # after changing models (docs/erd)
```
